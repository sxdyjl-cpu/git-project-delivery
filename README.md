# Git 项目交付 · git-project-delivery

用于产品、设计与研发协作的 Codex Skill。把产品需求、交互 Demo、版本变更和验收记录放进同一个 Git 交付项目，团队可以从版本目录打开对应需求正文和原型，并通过 Git 查看修改与评审记录。

## 安装与首次使用

1. [下载 Git 项目交付 1.0 安装包](./git-project-delivery-v1.0.zip)并解压。
2. 将解压出的 `git-project-delivery-v1.0` 文件夹复制到 Codex 的个人 Skill 目录，并将安装副本命名为 `git-project-delivery`。默认安装入口是 `~/.codex/skills/git-project-delivery/SKILL.md`。保留包内的脚本、模板和参考文档。
3. 在目标项目的 Codex 聊天中调用 `$git-project-delivery`。项目初始化和本地预览需要 Node.js 22 或更高版本，Git 协作需要 Git，正式 PRD 校验需要 Python 3.8 或更高版本。

## 可以用来做什么

| 场景 | 交付内容 |
| --- | --- |
| 新建产品交付项目 | 在独立文件夹生成版本总览、模块入口、文档阅读器、原型入口及协作规则。项目名称、主题和浏览地址可以配置。 |
| 接入已有需求 | 核对原文、需求 ID、版本和 Git 历史，建立可追踪的基线，沿用仓库现有的结构和协作规则。 |
| 编写正式 PRD | 1.0 随附 PRD Suite v2.0.0。新写或更新正式 PRD 时，使用原套件的模板和规则，通过 `ready` 校验后将 `PRD.md` 放入项目对应版本目录。 |
| 浏览需求和原型 | 版本目录按实际业务模块展示需求。点击条目打开正文，原型链接在新标签页或窗口直达对应页面及锚点。 |
| 研发交接 | 关联需求 ID、原型、验收条件和实现提交，按项目规则同步远端、处理并行修改并说明验证结果。 |

## 项目建成后如何持续迭代

- **开启下一版。** 沿用项目已有版本规则和 Git 仓库。确认新版本与需求范围后，建立版本目录、概要、需求文档和验收记录。延续到新版本的需求沿用原 ID。
- **调整已确认版本。** 新增需求与修改既有需求统一进入该版本的「变更需求」清单。新增单独记录，修改关联原需求并保留调整前后的规则。是否纳入与是否实现分别记录。

> 使用 $git-project-delivery，在当前仓库开启 v0.2，沿用原有版本规划。先整理本版需求范围和风险，更新对应原型与验收条件。

## 使用示例

**新建项目**

> 使用 $git-project-delivery，为「巡检助手」建立产品交付项目，版本用 v0.1，主题用青绿。先建立骨架，需求稍后提供，暂不发布。

**接入已有需求**

> 使用 $git-project-delivery，把当前目录的需求接入 Git 协作。保留原需求编号和已有版本，整理本版范围、风险、需求正文与原型的对应关系。

**连接远端仓库**

> 使用 $git-project-delivery，把当前项目连接到我提供的 Git 仓库，检查授权后完成首次推送。

## Git 授权与项目浏览

- 支持 GitHub、GitLab、Gitee 和团队自建 Git 服务。提供 HTTPS 或 SSH 克隆地址即可开始。没有仓库时，Skill 会核对平台、归属和可见性并引导创建。
- 优先复用本机已有的 HTTPS 凭据或 SSH 密钥。需要重新授权时，可在本机窗口填写令牌或平台允许的密码。装有 Git Credential Manager 时，可选用 GitHub.com 或 GitLab.com 的浏览器登录。
- 项目浏览 URL、Git 仓库网页地址和实际部署分别配置。可以先本地预览，是否上线由项目的发布流程决定。

安装包内的 `使用说明.md` 包含完整示例、目录说明和排障入口。
