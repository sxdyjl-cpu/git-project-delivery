# Git 项目交付 · git-project-delivery

用于产品、设计与研发协作的 Codex Skill。把产品需求、交互 Demo、版本变更和验收记录放进同一个 Git 交付项目，研发可以从版本目录打开对应需求正文和原型，并通过 Git 查看修改与评审记录。

## 可以用来做什么

| 场景 | 交付内容 |
| --- | --- |
| 新建产品交付项目 | 在独立文件夹生成项目骨架，包含版本总览、业务模块入口、文档阅读器、原型入口、构建检查和协作规则。项目名称、主题和浏览地址可以配置。 |
| 接入已有需求 | 核对原文、需求 ID、版本和 Git 历史，建立可追踪的需求基线。已有仓库沿用原有结构和协作规则，按需增量整理。 |
| 维护已确认的版本 | 每个版本集中展示需求范围、风险和应对，并把确认后新增与修改统一列入「变更需求」清单。记录调整原因、是否纳入及实现状态。 |
| 查看需求和原型 | 版本目录按实际业务模块展示需求，点击条目直达正文。原型链接在新的浏览标签页或窗口打开对应页面及锚点。 |
| 研发交接 | 关联需求 ID、原型、验收条件和实现提交。提交前检查差异，按项目规则同步远端并处理并行修改，交付时说明实际改动与验证结果。 |

## 安装与首次使用

1. [下载 Skill 安装包](./git-project-delivery.zip)并解压。
2. 将整个 `git-project-delivery` 文件夹放入 Codex 的个人 Skill 目录。默认路径为 `~/.codex/skills/`，确认 `~/.codex/skills/git-project-delivery/SKILL.md` 存在。保留包内的脚本、模板和参考文档。
3. 在 Codex 的目标项目聊天中调用 `$git-project-delivery`。初始化和本地预览需要 Node.js 22 或更高版本，提交和推送需要 Git。

**新建项目**

> 使用 $git-project-delivery，为「巡检助手」建立产品交付项目，版本用 v0.1，主题用青绿。先建立骨架，需求稍后提供，暂不发布。

**已有需求接入**

> 使用 $git-project-delivery，把当前目录的需求接入 Git 协作。保留原需求编号和已有版本，整理本版范围、风险、需求正文与原型的对应关系。

**连接远端仓库**

> 使用 $git-project-delivery，把当前项目连接到我提供的 Git 仓库，检查授权后完成首次推送。

## Git 授权与项目浏览

- 支持 GitHub、GitLab、Gitee 和自建 Git 服务。已有仓库提供 HTTPS 或 SSH 地址即可开始；还没有仓库时，Skill 会核对平台、归属和可见性并引导创建。
- 优先复用本机已有的 HTTPS 凭据或 SSH 密钥。需要重新授权时，可在本机窗口填写令牌，或在平台允许时填写账号密码。GitHub 的 HTTPS 接入使用令牌或平台登录。安装 Git Credential Manager 后，可选用 GitHub.com 或 GitLab.com 的浏览器登录。
- 仓库读写权限由平台和仓库管理员授予。Skill 会分别报告读取验证、推送预检和实际推送结果。凭据通过本机授权窗口或平台登录处理。
- 可分别配置项目浏览 URL 和 Git 仓库网页地址。上线由项目自己的部署流程决定，可先本地预览。已有项目有明确的迭代版本规范时直接沿用；缺少版本规划时由项目创建者确认。

安装包内的 `使用说明.md` 包含完整示例、目录说明和排障入口。`references/` 保存需求写作、交互原型、版本变更和研发交付规范，供 Skill 在执行时使用。
